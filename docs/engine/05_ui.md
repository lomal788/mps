# 05. 미니게임 공용 UI — 상태 표시(UIMGStatus)·UI 관리자·버튼 글자 (mps 판)

2026-10-06. 담당: ui-corner. 상태: **네 모서리 플레이어 상태 UI(얼굴·이름판·순위) 판독 완료**, **메시지 버튼 글자 치환 판독 완료**, **hsmg402 웹 구현**(`web/script/games/hsmg402/view/ui.ts`, 레이아웃 재생기 `web/script/view/lyt.ts`). 원본 실행 확인 없음. 웹 화면(헤드리스) 확인은 아직 안 했다(조정자가 마지막에 1회).

확정 수준: **[판독]** main 명령·디컴파일 판독, **[데이터]** 데이터 값 확인, **[재구현 계산]** 판독 식을 다시 계산, **[참고 이미지]** 사용자 원본 캡처(1280×720) 눈대중, **[추정]**, **[미확정]**. 원본 실행 확인은 이 문서에 없다.

주소는 SwitchLoader 기본 베이스 0x7100000000 기준 **main NSO** 주소다. 오프셋은 따로 적지 않으면 각 절에 적은 **기준 객체 시작**부터다. 디컴파일은 `analysis/decomp/ui/*.c`(Ghidra 복사본 `ghidra_work/ui/`, 명령 `ghidra_work/ui/core.sh`).

> **mpj(잼버리) 문서와의 관계.** mpj 의 UI 규칙(`C:/dev/mpj/web/docs/engine/05_ui_input.md`)은 다른 엔진 세대(CaComUiBase/ComUi)다. 레이아웃 파일 형식(FLYT/FLAN v9)은 같지만 클래스·메시지·이름 규칙은 이 문서의 mps 판독을 따른다.

## 1. 기능 개요와 사용자에게 보이는 동작

- 미니게임 중 화면 네 모서리에 플레이어마다 **원형 얼굴 아이콘 + 반투명 어두운 이름판**이 붙는다. 왼쪽 열은 아이콘이 바깥·이름판이 안쪽, 오른쪽 열은 좌우 반전. 위 줄은 이름이 아이콘 위쪽, 아래 줄은 아래쪽.
- 이름: 사람은 플레이어 이름(없으면 "게스트 k"), COM 은 캐릭터 이름("와리오" 등).
- 탈락 등으로 순위가 정해지면 아이콘 아래에 "1st"~"4th" 가 튀어 오르며 나타난다.
- 조작 가이드 같은 메시지 속 버튼 아이콘은 컨트롤러 상태에 따라 버튼 글자(Ⓐ Ⓑ Ⓧ Ⓨ) 또는 "버튼 위치" 아이콘으로 바뀐다.

### 4.5 부품 속성 덮어쓰기(ResPartsProperty 기본 정보 52 B) [데이터 + 추정]

`prt1` 속성 0x28 B: 이름 24 B, +0x18 usage, +0x19 basicUsage, +0x1a materialUsage, +0x1c 덮어쓰기 섹션 오프셋, +0x20 사용자 데이터, +0x24 기본 정보 오프셋. 기본 정보 = u32 ×2, 이동 f32×3, 회전 f32×3, 배율 f32×2, 크기 f32×2, 알파 u8(+48). **basicUsage 비트: 8 = 이동, 16 = 크기, 32 = 배율, 64 = 회전** [데이터: hs_system 전수 281건에서 값이 들어 있는 칸과 비트가 1:1(8·16·32·40·72·24·9)]. 비트 1·2·4 의 뜻(9 = x_parts_win 에만)은 [미확정]. 글자 덮어쓰기(txt1 섹션)의 usage 는 0 인데 정렬이 원본 캡처와 맞으려면 정렬이 적용돼야 한다 → 웹은 정렬만 쓴다 [추정]. 파서: `web/tools/analysis/ui_lyt.py read_prt`(basicInfo 추가).

## 6. 계산식·조건

### 6.1 순위 글자 `FUN_71000ccd4c(rank, 0)` [판독]

`x_text_01` 라벨 `hsmg_status_rank_small`("[0]"), 끼움 = rank 0 → `im_rank01`, 1~3 → 표 `0x71014aab38`(`im_rank02`·`03`·`04`) → "1st"·"2nd"·"3rd"·"4th". `x_text_02` 는 이 레이아웃에 없다. 그 뒤 `PlayPaneAnim("rank_on", 모듈 페인)`.

### 6.2 표시 이름 `GameWork::GetDispPlayerName(id)` @0x710003423c [판독]

플레이어 칸(GameWork + 0x18 + id·0x130 기준): +0x18 COM(== 1), +0x20 캐릭터 ID, +0x55 이름(플래그 10 이면 +0xf0 우선), +0xe4 처음 ID(`SetInitialPlayerID`).
```
온라인(DAT_71015e6a08 모드 1): id 0 = 계정 별명(GetAccountNickname), 그 밖 = 캐릭터 이름
로컬: 이름 있음 → (COM 이면 캐릭터 이름, 아니면 그 이름)
      이름 없음 → COM 이면 캐릭터 이름(CharacterList::PCNameLabel = im_pcNN_name)
                 아니면 k = #{ j ≠ id : 처음ID(j) < 처음ID(id) && 이름(j) 없음 }, 라벨 [im_guest01, 02, 03, 01][k]
```
결과는 UTF-8 32바이트 이하(넘으면 abort).

E000~E003 글리프는 `hsfont_middle_extension` 의 "버튼 위치" 아이콘(네 원 중 하나 채움), E004~E007 은 Ⓐ Ⓑ Ⓧ Ⓨ [데이터: 글리프 표]. 같은 치환이 `FUN_7100094520`·`FUN_7100094920` 에도 있다.

### 6.4 얼굴 텍스처 `UISharedTexture::GetPCFace(chara, kind)` @0x71000c4360 [판독]

`sprintf("face_%s_pc%02d^%s", 크기[kind], PCNumber(chara), 접미[kind])`, kind 0 = (`128`, `u`) ← 페인 이름 끝 `_pc128`, 1 = (`256`, `u`), 2 = (`front64`, `q`). `x_face_pc128` → `face_128_pcNN^u`(128×128).

### 6.4.1 얼굴 그리기 — 맵 슬롯과 투영 좌표

`SetPicturePCFace(pane, chara, 1)` → `bex::Layout::SetPictureUI2DTextureInfo(pane, tex, 1)` @0x710013839c 가 `*(재질+0x18 + 1·0x10 + 8) = tex` 로 **텍스처 맵 1** 을 바꾼다 [판독]. 맵 0(원 마스크)은 그대로다. 그리기 = 맵 0(정점 UV, mirror → 원) × 맵 1(얼굴).

맵 1 좌표(source 4) 식 [추정: 후보 비교]: 페인 사각형 가운데 기준 정점 위치 (x, y↑)에서 u = x/(texW·scale.x) + 0.5, v = −y/(texH·scale.y) + 0.5(texW·H = 얼굴 텍스처 128), 그 뒤 texSrt 1(배율 1.3, 가운데 기준) → 108 px 페인 모서리 UV −0.0484~1.0484(얼굴 한 장, clamp). 후보 6개를 원본 캡처 좌상 마리오 아이콘과 비교한 평균 절대 오차: 텍스처 128 × 1.3 = **0.101**, 페인 108 × 1 = 0.169, 페인 108 × 1.3 = 0.214, 텍스처 128 × 1 = 0.253, 페인 108 / 1.3 = 0.279, 텍스처 128 / 1.3 = 0.314(`web/tools/analysis/hsmg402_face_proj_fit.py`) [참고 이미지]. ui2d 투영 코드 자체는 판독하지 않았다(맞춤 플래그·flags 4 의 뜻 [미확정]).

**고치기 전 웹의 깨짐 원인:** ① 얼굴을 맵 0(마스크 자리)에 넣어 mirror 랩 + 정점 UV 0~2 로 상하좌우 뒤집힌 얼굴 4장이 나옴 ② 맵 1 좌표 생성을 무시해 정점 UV 를 썼다.

### 6.5 통신 아이콘 `hs::ut::UpdateRttIcon` @0x71000dc000 [판독]
